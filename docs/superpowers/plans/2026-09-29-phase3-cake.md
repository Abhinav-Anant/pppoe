# Phase 3 — Aggregate CAKE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use `- [ ]`.

**Goal:** Aggregate queue management on the uplink with CAKE, both directions handled explicitly, generated from the node model, applied under confirm-or-revert, persisted without Python in the boot path, observable via `bngctl qos status`, and demonstrated (shaping, latency under load, fairness) with measured numbers.

**Architecture:**

```text
Customer -> Internet : pppN -> (forward, SNAT) -> uplink EGRESS  -> CAKE  (upload,  dual-srchost nat)
Internet -> Customer : uplink INGRESS -> mirred redirect -> IFB bngifb0 EGRESS -> CAKE (download, dual-dsthost nat ingress) -> (un-NAT, forward) -> pppN
```

Per-subscriber limits stay in accel-ppp's shaper on each `pppN` (Phase 1); CAKE here is the
single aggregate queue per direction — no per-subscriber tc classes. `nat` makes CAKE look up
conntrack so host isolation sees the subscriber's private address, not 43.229.72.90.

Rendering produces `/etc/bng-platform/tc/cake.sh` (plain `/bin/sh`, only model-validated
values). `bng-qos.service` (oneshot) runs it at boot — no Python in the data-plane boot path.
Changes: `bngctl qos apply` runs a pending script under a 120 s revert timer
(revert = clear + run last confirmed script), `bngctl qos confirm` persists it.

**Facts verified on bng01 (kernel 6.8, iproute2 6.1):** `cake` available; `cake_mq` not
(kernel module lacks it, tc says unknown kind); IFB, `ingress`/`clsact`, `mirred`, `matchall`
available; accepted options: `bandwidth rtt diffserv3/4/8 besteffort flowblind srchost dsthost
hosts flows dual-srchost dual-dsthost triple-isolate nat nonat wash nowash split-gso
no-split-gso ack-filter ack-filter-aggressive no-ack-filter memlimit fwmark ptm atm noatm
overhead raw conservative mpu ingress egress`. CAKE has **no ECN switch** (it always ECN-marks
ECN-capable flows) — not exposed. `tc -s -j` gives per-tin drops/ecn_mark/backlog/delays.

**Uplink capacity (measured 2026-09-29, lower bounds):** download ~510–545 Mbit/s, upload
~680–717 Mbit/s (8 parallel streams; single stream ~150–210). Provisional CAKE: download
480 Mbit/s, upload 650 Mbit/s — replace with the contracted rate.

## Tasks

1. **Model** (`model.py`): `CakeDirection(bandwidth_mbit 1–400000, diffserv, isolation, ack_filter)`,
   `Cake(enabled, mode cake|cake_mq, rtt_ms, overhead None|-64..256, mpu None|0..256,
   link_layer noatm|atm|ptm, nat, wash, upload, download)`, `Qos(cake)`, `BngConfig.qos`.
   Defaults: upload isolation `dual-srchost`, download `dual-dsthost`, diffserv `besteffort`,
   ack_filter `no-ack-filter`, nat true. Tests: defaults, bounds, unknown option rejected.
2. **Capability detection + render** (`app/qos/cake.py`): `parse_capabilities(help_text) -> set`,
   `detect() -> {"cake": bool, "cake_mq": bool, "options": set}` (tests `lo` add/del + help
   text), `render(cfg) -> str` script (clear → IFB + download CAKE → redirect installed last →
   upload CAKE; disabled/no qos → clear only), `IFB = "bngifb0"`. Tests: both directions present
   with correct keywords, redirect line after IFB CAKE, `ingress` only on download, `ack-filter`
   only where configured, cake_mq refused when not detected, no per-subscriber rules.
3. **Status + health + CLI**: `parse_cake_json(json) -> dict(bandwidth_mbit, bytes, packets,
   drops, overlimits, backlog, ecn_mark, ack_drops, avg/peak_delay_us)`; `health.check_cake`;
   `bngctl qos status|capabilities|apply|confirm`; generic confirm-or-revert helper shared with
   the firewall (`app/networking/guard.py`, AccuracySec=1s).
4. **System**: `system/systemd/bng-qos.service`, installer installs/enables it, creates
   `/etc/bng-platform/tc`; uninstall clears qdiscs/IFB.
5. **On bng01**: apply with test value (download 100, upload 100 Mbit/s), measure host
   download/upload (expect ≤ ~100), ping RTT idle vs loaded with CAKE on vs off, fairness host vs
   lab subscriber (dual-dsthost), capture `tc -s -j` fixture; then apply provisional
   480/650, confirm, reboot-free persistence check via `systemctl restart bng-qos`.
6. **Docs**: `docs/phase3-results.md`, `docs/configuration.md` qos keys + direction table, README.
